# Code Review: `internal/config` + `internal/mappings` + `assets/`

## `assets/categories.yaml`

**⚠️ Занадто загальні ключові слова `"оплата"` і `"плата"` у категорії `Внески` (credit)**

`"оплата"` зустрічається в описах майже будь-якої транзакції. Оскільки
категоризатор має окремі кеші для debit/credit — пряме зіткнення між
`Комунальні` (debit) і `Внески` (credit) відсутнє. Але будь-яке надходження
з описом типу `"оплата послуг"` від контрагента потрапить у `Внески` замість
`Контрагенти`. Рекомендація — прибрати `"оплата"` і `"плата"` з `Внески`,
залишити лише специфічні: `"внесок"`, `"внески"`, `"квартплата"`,
`"кварт плата"`.

**⚠️ `"електро"` у `Комунальні` — занадто коротке**

Спрацює на `"електронний переказ"`, `"електронна пошта"` тощо. Краще
`"електроенергія"` або `"електропостачання"`.

**⚠️ `"оплата"` є одночасно в `Комунальні` (debit) і `Внески` (credit)**

Формально не конфлікт через роздільні кеші, але при майбутньому
рефакторингу категоризатора (наприклад, прибранні type-aware логіки) це
стане непомітним джерелом помилок. Варто прибрати дублювання або
задокументувати.

**⚠️ Відсутня категорія для переказів між власними рахунками**

Переказ власних коштів (поповнення депозиту, переказ між картками) не
матиме категорії і потрапить у `Uncategorized`. Варто додати:

```yaml
Власні перекази:
  type: credit
  keywords:
    - власний рахунок
    - поповнення рахунку
    - між рахунками
```

## `assets/column_mappings.yaml`

**⚠️ `privatbank_csv` — відсутній варіант `"Дата проводки"`**

Присутній у секції `privatbank_xlsx`, але відсутній у `privatbank_csv`.
ПриватБанк у різних версіях CSV-експорту використовує обидва варіанти.
Варто додати до списку кандидатів поля `date`.

**⚠️ `privatbank_xlsx` — відсутній варіант `"Дата і час операції"`**

ПриватБанк інколи експортує XLSX з колонкою `"Дата і час операції"` замість
`"Дата і час проводки"`. Варто додати до списку кандидатів.

**⚠️ Відсутній маппінг `edrpou` у `privatbank_xlsx`**

`privatbank_csv` містить:
```yaml
edrpou:
  - "ЄДРПОУ кореспондента"
  - "ЄДРПОУ контрагента"
```

XLSX виписки також містять ЄДРПОУ. Поле не критичне для звіту, але корисне
для `ProviderResolver` при пошуку контрагентів. Варто додати для симетрії.

**✅ `balance`, `debit`, `credit` є тільки в `privatbank_xlsx`** — коректно,
CSV не містить цих полів.

**✅ Merge-логіка в `mappings.Load()`** — дефолти доповнюються з YAML, а не
замінюються повністю. Правильне рішення.

## `internal/mappings/categories_config.go`

**⚠️ `defaultCategoriesConfig` може розсинхронізуватись з `assets/categories.yaml`**

Немає механізму що гарантує синхронізацію при майбутніх змінах YAML.
Рекомендація — додати коментар або unit-тест що порівнює ключі дефолтів
з завантаженим YAML:

```go
// УВАГА: defaultCategoriesConfig має збігатись з assets/categories.yaml.
// При зміні YAML — оновити і дефолти.
```

**⚠️ `yaml.v2` замість `yaml.v3`**

```go
import "gopkg.in/yaml.v2"
```

Всі файли пакету `mappings` використовують `yaml.v2`. У `go.mod` присутні
обидва `yaml.v2` і `yaml.v3`. Варто уніфікувати на `yaml.v3` — він підтримує
`time.Time`, кращу обробку помилок і `yaml.Node` для складних випадків.

## `internal/mappings/mapping.go`

**⚠️ Порожній маппінг при помилці `ForParser` призводить до оманливого логу**

```go
m, err := cfg.ForParser(privatbankCSVKey)
if err != nil {
    log.Printf("[PrivatBankCSV] маппінг не знайдено, використовую порожній: %v", err)
    m = mappings.ParserMapping{}
}
```

При порожньому маппінгу `utils.FirstMatch` повертає `-1` для всіх колонок,
і парсер поверне `"не знайдено колонку дати"`. Це помилка програміста
(відсутній ключ у дефолтах), а не користувача. Варто `panic` або `log.Fatal`
— дефолти мають покривати всі зареєстровані парсери завжди.

## `internal/mappings/providers_config.go`

**✅ Порожній дефолт при відсутньому файлі** — коректно, `assets/providers.yaml`
є у `.gitignore` (містить персональні дані).

**⚠️ `assets/providers.yaml` у `.gitignore`, але `config.Load()` завжди намагається його завантажити**

При запуску з іншої робочої директорії файл не знайдеться і буде
використано порожній дефолт з попередженням у лозі. Не критично (fallback
є), але варто задокументувати що файл опціональний і де він має лежати
відносно бінарника.

## `internal/mappings/report_config.go`

**✅ Дефолти збігаються з `assets/report_311.yaml`.**

**⚠️ `Report311Config` не валідується проти `CategoriesConfig` при старті**

Якщо у `report_311.yaml` вказана категорія якої немає у `categories.yaml` —
звіт згенерується з порожніми колонками без жодного попередження. Варто
додати валідацію при `config.Load()`:

```go
func ValidateReport311Config(cfg Report311Config, cats CategoriesConfig) []string {
    var warnings []string
    for _, sc := range cfg.SubColumns {
        if _, ok := cats[sc.Category]; !ok {
            warnings = append(warnings,
                fmt.Sprintf("report_311: категорія %q не знайдена у categories.yaml",
                    sc.Category))
        }
    }
    return warnings
}
```
