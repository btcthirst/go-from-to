# Тестування

Проект включає набір одиничних, інтеграційних тестів та бенчмарків для перевірки коректності та продуктивності.

## Запуск тестів

### Всі тести
```bash
make test
```

### Тести з детальним виводом
```bash
make test-verbose
```

### Швидкі тести (без інтеграційних)
```bash
make test-short
```

### Тести із звітом покриття
```bash
make test-coverage
```

Звіт будет генеровано у файл `coverage.html`.

## Бенчмарки

### Запуск всіх бенчмарків
```bash
make benchmark
```

### Бенчмарки для специфічного пакету
```bash
make benchmark-reader
make benchmark-config
make benchmark-app
```

## Структура тестів

### `internal/excel/reader/reader_test.go`

Тестує функції читання та обробки файлів.

#### Одиничні тести
- **TestFindAccountInCounterparty**: тестує пошук рахунків у даних контрагента
  - ✅ Рахунок знайдено
  - ✅ Рахунок не знайдено
  - ✅ Порожні дані
  - ✅ Карта рахунків порожня
  - ✅ Декілька збігів

- **TestIsValidName**: тестує валідацію імен
  - ✅ Українські букви
  - ✅ Латинські букви
  - ✅ Мішані букви
  - ✅ Чисті числа (невалідні)
  - ✅ Числа з розділювачами (невалідні)
  - ✅ Порожні рядки

#### Бенчмарки
- **BenchmarkFindAccountInCounterparty**: вимірює продуктивність пошуку на великих картах (10,000 рахунків)
  - ~159 μs на операцію з 0 алокацій
  
- **BenchmarkIsValidName**: вимірює продуктивність валідації імен
  - Дуже швидко (~100 ns)

### `internal/config/config_test.go`

Тестує модуль управління конфігурацією.

#### Одиничні тести
- **TestLoad**: тестує завантаження конфігурації з YAML файлу
  - ✅ Успішне завантаження
  - ✅ Валідація структури

- **TestLoadNonExistentFile**: тестує обробку помилок при неіснуючому файлі
  - ✅ Повертає помилку

- **TestGetDocumentConfig**: тестує отримання конфігурації для документа
  - ✅ Знайдена конфігурація
  - ✅ Невірна конфігурація

- **TestGetColumnIndex**: тестує отримання індексу колонки
  - ✅ Існуюча колонка
  - ✅ Неіснуюча колонка

- **TestIsValidRow**: тестує валідацію рядків за конфігурацією
  - ✅ Валідний рядок
  - ✅ Рядок без обов'язкових колонок
  - ✅ Рядок замало колонок

#### Бенчмарки
- **BenchmarkGetDocumentConfig**: вимірює отримання конфігурації
- **BenchmarkIsValidRow**: вимірює валідацію рядків

### `internal/app/app_test.go`

Тестує основну логіку обробки платежів.

#### Одиничні тести
- **TestProcessPayments_Basic**: тестує базову обробку платежів
  - ✅ Рахунки знаходяться
  - ✅ Класифікація платежів та відрахувань
  - ✅ Рахунки не знаходяться

- **TestProcessPayments_EmptyPayments**: тестує обробку порожного списку
  - ✅ Повертає порожний результат

- **TestProcessPayments_EmptyAccountMap**: тестує без карти рахунків
  - ✅ Дані зберігаються, рахунки не знаходяться

- **TestProcessPayments_ConsistentData**: тестує консистентність даних
  - ✅ Дати та суми зберігаються
  - ✅ IsDeduction залежить від знаку

#### Бенчмарки
- **BenchmarkProcessPayments**: вимірює обробку 1,000 платежів з 500 рахунками

### `internal/app/integration_test.go`

Інтеграційні тести, що тестують взаємодію компонентів.

#### Інтеграційні тести (запускаються тільки з `go test`, а не з `-short`)
- **TestIntegration_FullWorkflow**: повний цикл з конфігурацією
  - ✅ Завантаження конфіку
  - ✅ Обробка платежів
  - ✅ Перевірка результатів

- **TestIntegration_LargePaymentBatch**: обробка великого пакету (10,000 платежів)
  - ✅ Мірує продуктивність
  - ✅ Перевіряє коректність

- **TestIntegration_DeductionClassification**: перевіряє класифікацію платежів
  - ✅ Позитивні суми = платежі
  - ✅ Негативні суми = відрахування

## Покриття кодом


Це створить файл `coverage.html` з детальним звітом.

## Практики тестування

### Одиничні тести (Unit Tests)
- Тестують окремі функції в ізоляції
- Швидкі для запуску
- Легко налагоджувати

### Інтеграційні тести (Integration Tests)
- Тестують взаємодію компонентів
- Повільніші, але більш реалістичні
- Використовуйте `if testing.Short()` для опціональних тестів

### Бенчмарки (Benchmarks)
- Вимірюють продуктивність
- Виконуються з `-bench` флагом
- Допомагають выявити проблеми продуктивності

## Додавання нових тестів

1. Створіть файл `*_test.go` у тому ж каталозі, що і тестований код
2. Напишіть функцію `TestXxx(t *testing.T)`
3. Використовуйте `t.Errorf()`, `t.Fatalf()` для помилок
4. Запустіть `make test` для перевірки

Приклад:
```go
func TestMyFunction(t *testing.T) {
    result := MyFunction("input")
    if result != "expected" {
        t.Errorf("expected 'expected', got %q", result)
    }
}
```

## CI/CD Інтеграція

Рекомендується додати запуск тестів у CI/CD pipeline:
```bash
go test -short ./...        # Швидкі тести
go test ./...               # Всі тести
make test-coverage          # Звіт покриття
make benchmark              # Бенчмарки
```
